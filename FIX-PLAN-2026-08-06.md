## 3. TIER C — numerics-changing. **Each needs a new config toggle defaulting to CURRENT behavior.**

### C1. `full_cov_congruence_precision` — the largest single perf win. *(F3)*
`vfe3/geometry/transport.py:2736,2744,2751` (and `:2884-2886`, `:2600-2621`) hard-code `.double()`
with **no toggle at all**. This is now the largest stage in the step: 1.573 GFLOP in fp64 over
~1.57 GB, at 0.83 FLOP/byte, on a card whose fp64 rate is ~1/64 of fp32.

Add `full_cov_congruence_precision: "fp64" | "fp32_escalate"`, **default `"fp64"`** so nothing on
disk changes. Mirror `full_cov_kl_precision`'s structure. The escalation predicate already exists
next door at `transport.py:1412` (`_escalate_if_negative`) and needs an SPD rather than a sign
trigger. Expected 2–8x on this stage.

### C2. Make the `fp32_escalate` escalation trigger actually reachable. *(F1)*
`vfe3/families/gaussian.py:711` gates on `bool((~ok).any())` from `safe_cholesky(rounds=5)`, whose
absolute jitter ladder repairs every fp32 PD loss (75/75 at cond 1e9, 141/141 at 1e10, zero failures
below 1e8). The branch is dead code, so the policy is unconditional fp32.

Replace the trigger with an **accuracy** proxy computable in the working dtype — e.g.
`diag(L).min()^2 / diag(L).max()^2` as a free Cholesky-based conditioning estimate — against a
threshold like 1e-5.

**Severity note, so this is not over-built:** at the trained operating point the repo's own recorded
conditioning is median 2.7e3 / p95 2.1e4 (`config.py:854-856`), where the fp32 error gives an
attention-weight ratio of 1.0000–1.0002 — i.e. **the documented 4e-6 bound is correct where the model
actually lives.** The exposure is only that nothing guards an excursion, and C4 makes excursions
possible. Gate the new trigger behind the existing `full_cov_kl_precision` value so `"fp64"` is
untouched; the new predicate changes behavior only within `"fp32_escalate"`, so it needs its own
sub-toggle or a version bump on the policy string.

### C3. Scale `safe_cholesky`'s jitter to the matrix. *(F18)*
`vfe3/numerics.py:230`: `M + (eps * 10.0**t) * eye` is absolute. At an eigenvalue on the `eps=1e-6`
floor the `t=0` ridge **doubles** it and shifts `logdet` by exactly `log 2` per floored direction; at
`sigma_max=100` the same ridge is a 1e-8 no-op. Change to `eps * 10^t * diagonal_mean(M)` behind a
toggle (`safe_cholesky_jitter_mode: "absolute" | "relative"`, default `"absolute"`). Note this
interacts with C2 — do C2 first and re-measure, since a relative ridge makes `ok` a *slightly* better
signal but still not an accuracy signal.

### C4. Tighten `e_sigma_q_trust`. *(F7)* — **config default change, ask before flipping**
`e_sigma_q_trust=10.0` bounds `||R||_F <= 10`, permitting a **20-nat** one-step eigenvalue excursion
against an 18.42-nat admissible band. This is the mechanism that makes C2's exposure reachable.
Recommended `<= 2` (≈4 nats/step). **Do not change the default silently** — implement the
instrumentation half now (below) and put the value change in the PR description as a recommendation.

Instrumentation half, do now, no toggle: `condition_number` (`vfe3/numerics.py:289`) and its
`@register_monitor` wrapper (`:400-403`) have **zero production call sites** — `run_monitors` (`:406`)
is never called anywhere in `vfe3/`. Wire `condition_number(sigma_q).max()` into the per-step metrics
so this degradation is visible at all.

### C5. Fix the decode `-inf → NaN` path. *(F31)*
`vfe3/model/prior_bank.py:1144` sets `logdet_q = -inf` on Cholesky failure → `:1191` → `:1208` makes
every vocab logit `-inf` at that position → `:1241` `-inf - (-inf) = NaN` into the scalar CE; and
`:1213`'s `gathered * in_chunk_f` gives `-inf * 0.0 = NaN` independently. Latent (the jitter ladder
keeps `ok` all-True) but this is the *active* decode path. Replace the sentinel with a large finite
value, or mask the position out of `valid` at `:1215`. Toggle only if the change is observable on the
healthy path — verify it is not, then land it directly.

### C6. `apply_mu_trust_region`'s Cholesky fallback. *(F29)*
`vfe3/numerics.py:167` uses `rounds=0`, so one marginally non-PD `sigma_q` silently routes that batch
element to `:188-196`, which whitens by `sqrt(diag Sigma)` — **not** GL-equivariant (measured error
9.3e-2 / 6.6e-1 / 1.1e-1 vs the ball's 1.1e-15 / 1.1e-13 / 9.8e-11), masked in by `torch.where` with
no counter. Minimum fix, no toggle: emit the `ok`-mask fraction as a metric so the branch is
observable. Optional, toggled: `rounds>0`.

### C7. Pin and record fp32 matmul precision. *(F25)*
`vfe3/runtime.py:12-40` never sets `torch.backends.cuda.matmul.fp32_precision` / `allow_tf32`, while
`tests/conftest.py:61-99` does — so every test tolerance is pinned under a policy production neither
asserts nor logs, and `provenance.json` cannot record the drift. Set it explicitly in

user's card**, so gate the *setting* behind a config field defaulting to "leave as-is", but add the
*recording* unconditionally.

## 4. TIER D — experiment design. **Do not implement; write these up in the PR description.**

These need the user's judgement, not a patch.

- **D1 (F9).** No rank-only comparator is runnable. `ablation.py:1273`'s `diagonal` arm inherits
  `decode_mode="full_chunked"`, which `config.py:2333-2340` rejects, so the whole `covariance` sweep
  is dropped with an advisory. The `full` arm also overrides `lambda_alpha_mode`, confounding two
  factors. And `mm_exact` is structurally unreachable for `gaussian_full`
  (`gradients/kernels.py:299-309`), so the only descending comparator on disk differs in the *update
  rule*, not the covariance rank. **The ten sweeps running tonight are all optimizer/init
  hyperparameters — nothing architectural.** Proposed arm: `family_chunked` decode on *both* sides,
  `lambda_alpha_mode` held constant.
- **D2 (F11).** At this config `gaussian_full` buys exactly two things: within-head 10×10 correlation,
  and an untruncated transported key covariance in the pair energy. It is provably block-diagonal
  (the token prior is `diag_embed`-promoted, `sigma_log_embed` is `(V,20)` with no off-diagonal
  parameters) and the decode CE is provably blind to every off-diagonal entry (`per_pos` cancels
  exactly). Full 20×20 correlation needs a packed-Cholesky token prior, or `T>=2` / `L>=2`.
- **D3 (F12).** The self-coupling sector is **identically zero** at `T=1`: `model.py:1145-1146` passes
  the belief as its own prior, so `D(q||p)` and both its gradients vanish at the only iterate
  (sympy: exact zeros). `lambda_alpha`, `b0`, `c0` and the alpha-form are inert instruments. Run
  `T>=2` before reporting any alpha sweep.
- **D4 (F13).** Zero replication (`seed_design: [6]`, and training is *bitwise* deterministic, so
  repeat runs are not replicates); `primary_val_ppl` is a min-over-5-evals then argmin-over-arms
  double minimum; and no sweep ever scores a test split. Run the already-registered
  `multiseed_floor` (`ablation.py:909-922`, `seeds: [6,64,23,3,17]`, ~2 h) once before interpreting
  any ~2% gap; report `final_val_ppl` as primary; score the winner on test.
- **D5 (F21).** ~11 of ~54 arms are redundant: every sweep includes the baseline value and resume is
  scoped per-sweep-directory with no cross-sweep dedupe. ≈4 of ≈21 GPU-hours.
- **D6 (F23).** `eval_stride=None` makes the CE-vs-N curve a context-starvation measurement (mean
  context 32.5 at N=64 vs 128.5 at N=256), compounded by `pos_phi="learned"` clamping past
  `max_seq_len`. Set `eval_stride=64` for any cross-N comparison.
- **D7 (F24).** E-step LRs are unscheduled while M-step LRs decay 100×, so the E:M step-size ratio
  goes 6.7 → 667 over the run. Consider scheduling the inner loop, or documenting the drift.
- **D8 (F8).** An `n_heads` sweep at fixed `alibi_slope` silently rescales the positional prior by up
  to 180×. Pin the realized head-0 slope instead.
- **D9 (F28).** `group_product` composition permits an effective chart norm of 24 (two independently
  clamped factors of 12), against the codebase's own `< 20` design invariant. Project the *composed*
  chart or halve the per-table radius; and set `transport_chart_max_norm` so `validity_max_norm`
  fires on the `adamw` route.
