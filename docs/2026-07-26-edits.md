## Strided held-out evaluation (`cfg.eval_stride`), branch `feat/2026-07-26-eval-stride`

`vfe3/data/datasets.py`, `vfe3/config.py`, `train_vfe3.py`, `ablation.py`, `scaling.py`,
`vfe3/viz/report.py`, `tests/test_eval_stride.py` (+30 tests), plus three test stubs widened for the
new keyword.

**Why.** With disjoint held-out windows (`stride == seq_len`, the only thing the eval path could do)
the first target of every window is predicted from one token of context, the second from two, and so
on. The reported cross-entropy is inflated by that starvation, and the inflation grows as `seq_len`
shrinks -- at `max_seq_len = 128` the starved head is a large fraction of each window, not the small
one it would be at 1024.

**What.** `eval_stride` selects the standard sliding-window evaluation for validation and test: each
window still runs on its full `seq_len` of context, but only its final `stride` targets are scored
and the overlapping prefix is masked to `-100`. Every transition is therefore counted exactly ONCE,
at `seq_len - stride` tokens of context or better. The masked prefix is context, not padding --
`train.evaluate` already runs the model on the whole window and weights it by the count of
non-ignored targets, and `targets` never touch the E-step (only the decode and CE), so masking
changes what is averaged without perturbing inference. This is the recipe in HuggingFace's
fixed-length-model perplexity documentation.

**The exactly-once contract survives.** The recorded plan was to disable `pad_final` on the strided
path, which would have dropped the tail and given up exactly-once coverage. That turned out to be
unnecessary: `pad_final` already means "cover every transition once, padding and masking as needed",
and it generalizes to overlapping windows directly. Window `i` scores transitions
`[i*stride + seq_len - stride, i*stride + seq_len)`, which tile the stream contiguously from zero;
`n` is the fewest windows whose last one reaches the final transition, and the existing tail padding
handles the overrun. At `stride == seq_len` every formula reduces exactly to the old one
(`n == ceil(transitions / seq_len)`, mask covers zero positions), so `eval_stride=None` is
byte-identical to the previous behavior. Verified exactly-once at eleven shapes including the ragged
and single-window degenerate cases, and end-to-end through a real `DataLoader`: 400 tokens give 399
scored targets at stride 8, 4, 2 and 1 alike. `stride > seq_len` still fails closed under the eval
contract (it would leave gaps no mask can recover); the train contract, which shuffles and drops its
tail, still allows it.

**One live hazard fixed in passing.** `.to(torch.long)` is a no-op for an int64 stream, so the
returned `targets` is a VIEW into the corpus tensor. Masking it in place would have silently
corrupted the stream for every later window. The masking path clones first, and a test pins that
iterating leaves the stream bit-identical.

**Wiring.** All three drivers that publish held-out numbers honor it -- `train_vfe3._select_loader`,
`ablation.get_loader`, `scaling.get_loader` -- for validation/test only; train is never strided. The
stride is in each memoizing loader's cache key, without which a sweep over `eval_stride` would be
served the first arm's loader and every arm would report identical windows. `ablation`'s
extrapolation probe uses the same stride as the cell's own metric, so the CE-vs-N curve and the
headline PPL stay one measurement at different N. `vfe3/viz/report._build_loader` is deliberately NOT
strided and now says so: it feeds diagnostic figures, not a metric, and overlapping windows would
make consecutive figure batches near-duplicates. Provenance needed no change -- `run_artifacts`
already validates `stride`/`pad_final` generically, so the eval contract lands in the run record and
a resume under a different one is correctly flagged as drift.

**Comparability, which matters more than the code.** A strided number is a DIFFERENT METRIC from a
disjoint one and is always lower. It must not be compared against the existing baselines (55.41, the
172-vs-139 pair), which were all measured disjoint. The default stays `None` precisely so the whole
recorded history remains the comparable series; set `eval_stride` when you want a properly-contexted
figure to put beside an external baseline, and say which contract produced any number you report.
Measured on a period-5 stream a small model learns: CE 0.00114 disjoint against 0.00056 at
`stride = seq_len/2`, the starved window heads and nothing else.
