# Default-Off Per-Block MLP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an untied, position-wise residual MLP after each VFE block's current normalization and before prior handoff, with an exactly inert default-off path and explicit launcher toggles.

**Architecture:** `VFEModel` owns one `BlockMLP` per VFE layer when enabled and owns no MLP module when disabled. `vfe_stack` selects the layer-local module, `vfe_block` applies it only to the mean after the existing post-inference transforms and block norm, and covariance plus all other belief fields pass through unchanged. The coordinate MLP is reported as an optional mean-only, covariance-passthrough, non-gauge-pure structural augmentation.

**Tech Stack:** Python 3.14 CPU test interpreter, PyTorch `nn.Module`/`nn.ModuleList`, frozen dataclass configuration, pytest/JUnit, existing VFE3 optimizer/reporting/checkpoint infrastructure.

## Global Constraints

- The approved public schema is exactly `use_block_mlp=False`, `block_mlp_expansion=4`, `block_mlp_activation="gelu"`, `block_mlp_dropout=0.0`, and `m_block_mlp_lr=None`.
- `use_block_mlp=False` creates no MLP modules, parameters, optimizer groups, or state-dictionary keys and makes no forward-path call.
- The active MLP is untied across `n_layers`, is position-wise on the last `embed_dim` axis, and computes `mu + dropout(W2(activation(W1(mu))))` with standard linear biases.
- The active coordinate MLP leaves diagonal or full covariance bitwise unchanged and preserves every non-mean `BeliefState` field.
- Apply the MLP after `capture["converged"]`, optional head mixer/CG, and the existing block norm, and before the layer prior handoff.
- Reject active MLP with effective E-step estimator `detach`; support `unroll` and `straight_through`.
- The active route is a non-gauge-pure structural augmentation, not a VFE-derived update or nonlinear covariance pushforward.
- Expose all five controls explicitly in the editable dictionaries in `train_vfe3.py` and `ablation.py`; keep the toggle off.
- Register an MLP ablation but do not add it to default `SWEEP_ORDER`.
- Preserve the live checkout's existing `ablation.py`, `train_vfe3.py`, `vfe3/config.py`, and `zzzzz.py` WIP during final integration.

```python
class BlockMLP(nn.Module):
    def __init__(self, embed_dim: int, expansion: int, activation: str, dropout: float) -> None:
        super().__init__()
        hidden_dim = embed_dim * expansion
        self.fc1 = nn.Linear(embed_dim, hidden_dim)
        self.activation = _ACTIVATIONS[activation]()
        self.fc2 = nn.Linear(hidden_dim, embed_dim)
        self.dropout = nn.Dropout(dropout)

    def forward(self, mu: torch.Tensor) -> torch.Tensor:
        return mu + self.dropout(self.fc2(self.activation(self.fc1(mu))))
```
