# 2026-07-25 edits

## Frame-intrinsic Gaussian family (default OFF)

Adds `family="gaussian_frame_diagonal"`, a covariance declared diagonal in the agent's own fiber
frame, `Sigma_i = U_i diag(sigma_i) U_i^T`. That family IS closed under GL(K), unlike the
fixed-basis `gaussian_diagonal` whose congruence is truncated to its diagonal by
`transport_covariance`.

- `vfe3/families/base.py` — new `transport_location` classmethod, the location-side twin of the
  existing `transport_dispersion`. Default delegates to `transport_mean`, so every existing family
  is byte-identical.
- `vfe3/families/frame_gaussian.py` — new. `FrameDiagonalGaussian` subclasses `DiagonalGaussian`
  (same divergence/natural/log-partition algebra) and overrides only the two transport seams, both
  of which become a query-axis broadcast view. `block`/`broadcast_over_keys`/`stack` overridden to
  preserve the subclass.
- `vfe3/families/__init__.py` — import so the family registers.
- `vfe3/gradients/oracle.py` — two `transport_mean(omega, mu_k)` call sites now dispatch through
  `fam.transport_location(mu_k, omega)`; orphaned `transport_mean` import removed.
- `ablation.py`, `scaling.py`, `train_vfe3.py` — the new value documented on the `family` toggle.
- `tests/test_frame_gaussian_family.py` — new, 8 tests, all K < 6 and CPU-bound.

The kernel route is registered per family (`kernels.py:93`), so this family falls through to the
generic oracle path automatically; no gating was needed.

**Consequence, verified not assumed.** For the Regime-I coboundary `Omega_ij = U_i U_j^{-1}` the
sender frame cancels from the congruence and the receiver frame from the location, so the pair
energy depends only on `(a_i, sigma_i, a_j, sigma_j)` with `a = U^{-1} mu`. The gauge therefore
leaves the belief coupling entirely. End-to-end this shows up as `phi_embed.grad is None` — under
this family the 452M gauge table receives no gradient at all. That is pinned by
`test_frame_family_leaves_the_gauge_table_without_gradient`. The toggle is an ablation of whether
the gauge earns its keep, not a drop-in improvement, and is default OFF for that reason.

**Known follow-up:** the stack still builds the transport before dispatching to the family, so a
run with this family does wasted work constructing an `omega` nobody reads. Worth a
`family.consumes_transport` short circuit if the arm proves interesting.

**Pre-existing test failures, not caused by this work:** `test_gauge_optim.py::
test_single_head_forward_matches_recompute_dense_low_level_oracle[rope-gradient|rope-mm-exact]` and
`test_p3_pairwise_stats_reuse_20260711.py::

## Exact-congruence Gaussian family (default OFF) — implemented

Adds `family="gaussian_diagonal_exact"`. Same DISTRIBUTION family as `gaussian_diagonal` (same
self-divergence, natural parameters, decode, retraction); only the belief-COUPLING energy differs.
Instead of pushing the key forward and truncating `Omega diag(s_j) Omega^T` to its diagonal, it
pulls the QUERY back by `Omega^{-1}` — a divergence is invariant under a common invertible
pushforward — which leaves the second argument exactly diagonal and needs the first only through
its diagonal and its determinant:

    KL( N(mu_i, diag s_i) || N(Omega mu_j, Omega diag(s_j) Omega^T) )
      = KL( N(Omega^{-1} mu_i, Omega^{-1} diag(s_i) Omega^{-T}) || N(mu_j, diag s_j) )

    trace  = sum_k [Omega^{-1} diag(s_i) Omega^{-T}]_kk / s_j,k
    mahal  = sum_k ( mu_j,k - [Omega^{-1} mu_i]_k )^2 / s_j,k
    logdet = sum_k log s_j,k - sum_k log s_i,k + 2 log|det Omega_ij|

Unlike `gaussian_frame_diagonal`, the gauge STAYS in the energy: `phi` keeps its gradient.

### The seam

`BeliefParams.coupling_energy(mu_q, sigma_q, mu_k, sigma_k, omega, ...)` is new in
`vfe3/families/base.py` — the single dispatch point for the whole transported pair grid. Its default
body is the `transport_location` + `transport_dispersion` + `pairwise_energy` composition the call
sites used to inline, so every existing family is byte-identical (pinned by
`test_default_coupling_seam_matches_the_inlined_transport_triple`). The exact congruence CANNOT be a
`transport_*` override: those seams receive only the KEY, and the pullback needs the live QUERY leaf
(computing it from the detached key copy would zero the filtering gradient outright).

Call sites routed through the seam: `gradients/oracle.py` (belief gradient, plus the decoupled RoPE
value energy), `inference/e_step.py` (`free_energy_value`, `phi_alignment_loss` — so the phi step
descends the same energy), `model/model.py` (the s-channel gamma coupling in the forward loss, plus
the beta-map / diagnostics replays), `viz/extract.py`. `metrics.py`'s equivariance residual is
deliberately NOT routed: it pins `gaussian_full` on purpose and never reads `cfg.family`. The hand
kernels in `gradients/kernels.py` are untouched — they are `gaussian_diagonal`-only, so the new
family falls through to the oracle automatically and `mm_exact` is rejected by the existing
`uses_kernel_route` predicate with no config edit.

### Two routes

FAST (certified flat cocycle). For `Omega_ij = U_i U_j^{-1}` the inverse is the pair TRANSPOSE,
`Omega_ij^{-1} = Omega_ji`, so the backward-transported query is the ordinary forward transport of
the query array read at the swapped index. Every existing fast path (block-factored diagonal
sandwich, compact blocks, per-head mean, certified self links) is reused verbatim, and
`log|det Omega_ij| = ell_i - ell_j` needs only per-vertex block log-determinants.

REFERENCE (dense pairwise `omega`). `Omega^{-1}` is formed explicitly and pair determinants taken per
block. Assumes nothing about the connection, so it is the oracle the fast route is pinned against;
`O(N^2 K^3)`, for tests and small dense-transport configs only.

Anything else — regime_ii, direct-link, RoPE-wrapped, an uncertified factored cocycle, unequal
transport blocks (the so_n/sp_n towers) — RAISES. So does a non-KL divergence: the pullback identity
is KL-specific, because a Renyi blend of the dense pushforward with a diagonal covariance does not
reduce. Nothing silently falls back to the truncated energy.

### Measured

Exactness (float64, `tests/test_exact_congruence_family.py`, 19 passed): the energy matches a dense
reference `KL(N(mu_i, diag s_i) || N(Omega mu_j, Omega diag(s_j) Omega^T))` to ~3e-13 per pair and
per irrep block, where the truncated form is off by >80 nats at cond(U) ~ 200. Factored, compact and
dense routes agree to 5e-13. Self-pairs are EXACTLY 0.0 (the softmax and the saturation mask depend
on that). With `Omega = I` the two families coincide exactly.

CUDA, at the live training shape (K=20, n_heads=2, block_glk, N=128, batch 16, RTX 5090, 4 timed
steps after 2 warmup):

| arm | ms/step | phi grad norm |
|---|---|---|
| `gaussian_diagonal` + `mm_exact` | 19.8 | 6.49e-05 |
| `gaussian_diagonal` + `gradient` | 18.0 | 7.83e-05 |
| `gaussian_diagonal_exact` | 20.4 | 1.67e-04 |

About 13% over the gradient baseline and 3% over `mm_exact` — the transpose route reuses the same
kernels, so the only new work is one slogdet per vertex block.

### Reduced precision (AMP)

`torch.linalg` rejects bfloat16/float16 outright, so the first live run under `amp_dtype='bf16'`
crashed in the model channel's gamma coupling (`_gamma_energy` runs at the caller's autocast dtype;
the oracle and the hand kernels have their own fp32 islands, but that call site does not). The
log-determinant and the dense inverse are now promoted to fp32 and the determinant is RETURNED at
fp32 rather than cast back — it enters the energy additively, so a bfloat16 evaluation would be
wrong, not merely rounded. The surrounding contractions keep whatever precision the caller's
autocast context gave them, exactly as the default family's transported moments do. fp32/fp64
inputs pass through untouched, so the exactness pins are unaffected. Pinned by
`test_reduced_precision_transport_is_promoted_for_the_determinant` over all three routes.

Verified end to end afterward: two real `train_step`s on CUDA under the LIVE `train_vfe3.py` config
(`amp_dtype='bf16'`, `s_e_step=True`, `lambda_gamma=0.75`, `gamma_as_beta_prior=True`,
`oracle_unroll_grad=True`) — loss 10.82492 -> 10.82257 with `phi_embed` grad norm 1.62e-04, against
10.82493 -> 10.82264 / 8.84e-05 for `gaussian_diagonal` on the same config.

### Config requirements (documented on the toggle in all three config dicts)

- `divergence_family="renyi"` + `renyi_order=1.0` (KL only; raises otherwise).
- `e_step_update="gradient"` — no hand kernel, so `mm_exact` is rejected at config time.
- **`oracle_unroll_grad=True`** under `e_step_gradient="unroll"`. Without it the oracle returns a
  DETACHED tangent and `phi_embed` gets no gradient at all — silently a frozen-gauge run. Pinned in
  both directions by `test_gauge_table_keeps_its_gradient_under_the_exact_family`, which also pins
  that `gaussian_frame_diagonal` stays gradient-free under either setting (its cancellation is real,
  not an unroll artifact).

### RESULT: both arms are much worse, and the reason is the energy SCALE

Runs (K=20, block_glk, seed 6, 15000 steps; baseline `138.40_mstep-phi-norm=5` = val PPL 139.3):

| arm | val PPL | `guard_energy_klmax_frac` | `self_divergence` | `vertex_cond_median` |
|---|---|---|---|---|
| `gaussian_diagonal` (baseline) | **139.3** | **0.0000** | 0.008 | 47.3 |
| `gaussian_frame_diagonal` | 308.1 | 0.894 | 4.8 | 1.65 (phi frozen) |
| `gaussian_diagonal_exact` | abandoned; train PPL 432 @ step 7900 | **0.979** | 415 | 24.4 |

The exact arm never recovers: train PPL bottoms near 543 at step 2000, RISES to 622 by step 3300,
and is still 432 at step 7900 (best 407.5 at step 7400) against the baseline's 147 train / 139 val.
`self_divergence` runs 11 -> 213 -> 402 -> 415 and `belief_cond_median` 2.5 -> 24 over the same span.

Measured on the SAME trained state (the 138.40 checkpoint, `kl_max=160`, one sequence, energies
evaluated UNCLAMPED, off-diagonal pairs only; vertex cond(U) median 11.6 / p99 79.8 / max 108.9):

| energy `E_ij` (nats) | median | p90 | p99 | max | frac >= `kl_max` |
|---|---|---|---|---|---|
| truncated (`gaussian_diagonal`) | 5.65 | 13.79 | 21.75 | 58.9 | 0.0000 |
| exact (`gaussian_diagonal_exact`) | 34.10 | 326.72 | 1882.89 | **10912.2** | 0.1894 |

Exact/truncated ratio: median 7.2x, p90 66.9x, p99 426x, max 4604x. `kl_max` would have to exceed
~10900 rather than 160 for the exact energy not to clamp on a state the baseline runs at 0.0000
saturation.

**Why.** The truncated key covariance `diag(Omega diag(s_j) Omega^T)_k = sum_l Omega_kl^2 s_jl` is a
sum of squares: always inflated, never near-singular. The exact `Omega diag(s_j) Omega^T` IS
near-singular along the contracted directions of an ill-conditioned `Omega`, and KL against a
near-singular covariance grows like `cond(Omega)^2` through its trace term. The observed maximum
bears that out to within 10%: `cond_max = 108.9`, `cond_max^2 = 11858`, observed max energy 10912.
So the exactness fix is not a small correction; it is a different order of magnitude with a heavy
tail keyed to conditioning.

**The runaway.** Above `kl_max` the clamp emits a constant, whose derivative is zero, and
`pair_mask = (energy > 0) & (energy < kl_max)` then zeroes the pair derivative. That removes the one
term that would push `phi` back toward well-conditioned frames, so saturation is self-reinforcing:
0.06 -> 0.15 -> 0.20 -> 0.80 -> 0.97 -> 0.979 over 7900 steps, with beta washing back out toward
uniform (`attn_entropy` 2.48 -> 1.27 -> 2.41) as the grid flattens onto the clamp. The baseline holds
that metric at exactly 0.0000 for all 15000 steps.

**Reading.** The diagonal truncation is not an approximation error to be removed; it is the
regularizer that makes a genuinely non-compact GL(K) gauge usable. The exact congruence energy and
an ill-conditioned GL(K) frame are in direct tension: the exact form is tame only when `Omega` is
near-orthogonal, and precisely there the truncation error it removes is negligible, so the two paths
coincide and there is nothing to win. That tension is the finding; the implementation is correct
(pinned to 3e-13 against a dense reference), the model simply cannot run on the energy it computes
at this conditioning.

Both toggles stay default OFF and are kept as measurement instruments: the exact family quantifies
how much divergence mass the truncated attention score discards (median 7x, p99 426x), and the frame
family quantifies what the gauge channel is worth (139.3 -> 308.1 with `phi` disconnected).
